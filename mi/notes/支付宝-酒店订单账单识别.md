# 支付宝酒店订单账单识别

## 用途

`alipay_hotel_orders.py` 用于打开支付宝账单，按指定截止日期向下翻页，识别订单名为“酒店订单”的账单记录，并逐条进入详情页提取付款银行卡信息。

脚本只处理标题严格等于“酒店订单”的订单；其他订单不会进入详情，但会参与截止日期判断。

## 执行命令

从支付宝首页自动进入“我的” -> “账单”，解析 4 月 1 日及之后的酒店订单：

```bash
/Users/weichaofan/miniconda3/envs/py3.11/bin/python alipay_hotel_orders.py --end-date 4-1 --execute
```

如果当前已经在支付宝账单页：

```bash
/Users/weichaofan/miniconda3/envs/py3.11/bin/python alipay_hotel_orders.py --start-bill-page --account-phone "171 ******02" --end-date 4-1 --execute
```

保存 JSON 结果：

```bash
/Users/weichaofan/miniconda3/envs/py3.11/bin/python alipay_hotel_orders.py --end-date 4-1 --output alipay_hotel_orders.json --execute
```

本地解析自测：

```bash
/Users/weichaofan/miniconda3/envs/py3.11/bin/python alipay_hotel_orders.py --self-test
```

## 参数

- `--execute`：实际操作手机。没有该参数时是 dry-run，不会点击或滑动。
- `--end-date 4-1`：截止日期，包含当天及之后的订单。支持 `4-1`、`4月1日`。
- `--year 2026`：账单列表只显示月日时，脚本用该年份补全日期；默认当前年份。
- `--start-bill-page`：假设当前已经在支付宝账单列表页。
- `--account-phone`：配合 `--start-bill-page` 使用，手动传入账号标识。
- `--max-scrolls`：最多向上滑动多少次，默认 20。
- `--output`：将最终正常结果保存为 JSON。

## 流程

1. 启动支付宝。
2. 点击底部“我的”。
3. OCR 识别账号，输出 `ACCOUNT ...`。
4. OCR 定位“账单”入口并点击进入。
5. OCR 当前账单列表页订单。
6. 解析当前屏幕所有订单日期。
7. 仅对标题等于“酒店订单”的订单进入详情页。
8. OCR 详情页字段。
9. 返回账单列表页，继续处理当前屏其他酒店订单。
10. 当前屏处理完后，向上滑动半屏。
11. 循环，直到当前屏出现任意订单日期早于 `--end-date`。

## OCR 区域

脚本不是整屏 OCR，而是裁剪关键区域：

- 我的页账号：`(230, 185, 720, 390)`
- 我的页账单入口：`(0, 500, 520, 800)`
- 账单列表页：`(0, 330, 1080, 1960)`
- 账单详情页：`(0, 250, 1080, 1700)`

设备分辨率按 `1080x2340` 编写。

## 截止日期规则

`--end-date` 用于控制停止位置，例如 `--end-date 4-1` 表示解析 4 月 1 日及之后的酒店订单。

停止判断看的是当前屏幕上的所有订单，不限酒店订单。只要识别到任意订单日期早于截止日期，就停止继续滑动。

## 订单筛选规则

只处理订单名严格等于：

```text
酒店订单
```

便民餐车、退款、转账等其他订单只用于判断是否已经滑到截止日期之前，不会进入详情页。

## 详情页字段规则

详情页 OCR 提取：

- 支付时间
- 订单金额
- 付款方式
- 收款方全称

结果中的订单日期和订单时间以账单列表页时间为准。详情页支付时间只用于校验：与列表页时间相差 30 分钟以内即认为匹配。

金额优先使用详情页“订单金额”右侧数字；如果详情页没有订单金额，则回退到账单列表金额，并去掉正负号和千分位。

银行卡信息来自详情页“付款方式”，例如：

```text
农业银行信用卡(5229)
```

支付宝详情页只展示银行卡尾号，脚本无法获取完整卡号。

## 输出

脚本结束时输出：

- `FINAL_RESULTS`：正常识别且校验通过的酒店订单。
- `ABNORMAL_RECORDS`：异常记录，例如字段缺失、时间差超过 30 分钟、订单未能点击打开。

`FINAL_RESULTS` 中每条记录包含：

- `account_phone`
- `order_date`
- `order_time`
- `title`
- `amount`
- `bank_name`
- `card_tail`
- `payment_method`
- `merchant`
- `raw_order`

## 注意事项

- 脚本会操作真实手机，需要加 `--execute`。
- 如果手机黑屏或锁屏，先运行 `./unlock.sh`。
- PaddleOCR 首次初始化较慢，执行几分钟属于正常。
- 半屏滑动会导致相邻屏幕有重叠，脚本用订单原始信息去重，避免重复处理。
