# 单机代码部署

## 使用场景

用于通过接口模拟 `/dash/tools/common` 页面里的“代码部署 -> 新建部署”操作，创建单机代码部署任务。

## 执行前要求

1. 真正提交部署任务前，需要让用户确认下信息，如分支名、机器ip对不对
2. plan 里不要直接展示 `0`、`1`、`true`、`false` 这类机器参数，应翻译成用户能读懂的中文含义。
3. 提交前必须确认以下信息：
   - 部署 profile：例如主站点播线上环境（默认）、国际站点播线上环境、主站点播测试环境。
   - 部署机器 IP。
   - 部署分支。
   - 部署描述。
   - 月神环境分支名 `envName`，如果用户说默认或 master，则保持为空。
   - 用户 IP `remoteAddr`，如果用户未指定则保持为空。
4. 如果用户给的是已有 profile，按 profile 自动补齐固定参数，不要再逐项追问。
5. 如果只是创建单机代码部署任务，不需要更新本地 `star-map` 代码；该流程只调用线上星图接口，本地源码不参与部署。

## 按需求号部署

用户可以直接说“部署某个需求的代码到某台机器”，例如只给需求号、部署机器和环境。

处理规则：

1. 先根据需求号去查询对应的标题（使用`根据需求PMS号查询标题和备注等信息.md`技能）。
2. 如果需求描述里面有'dash','点播'，就说明是要部署点播环境，另外默认是线上环境。
3. 部署描述默认使用 "$PMS_标题 $PMS_NUM"。
5. 如果用户没有说部署机器，优先按 PMS 号查询需求备注（使用`根据需求PMS号查询标题和备注等信息.md`技能），从备注里的“联调环境”信息提取默认部署机器 IP；如果查不到明确 IP 或命中多个不同 IP，再询问用户确认。不能从历史部署记录中猜机器。
6. 如果用户没有明确分支名，且部署项目是点播 dash，则你通过远程 Git 分支查询完整分支名。
7. 如果远程 Git 也找不到明确分支名，或命中多个非自动分支，必须停下来问用户；不能猜分支。
8. 找到分支、机器和环境后，按单机部署流程给出可读 plan，等待用户确认。
9. 用户确认后再提交部署任务，并阻塞轮询到成功或失败。

### 按 PMS 备注查默认部署机器

当用户要求部署指定需求，但没有提供部署机器 IP 时，先参考 `skills/根据需求PMS号查询备注.md`，用 PMS 号查询该需求的备注。

从返回的 `comments` 数组中读取每条备注的 `comment_body`，优先查找包含“联调环境”的内容，并从其中提取 IPv4 地址。

例如备注内容为：

```text
联调环境：  10.128.55.136  cache.video.iqiyi.com
```

则 `10.128.55.136` 是该需求默认要部署的机器 IP，可以写入部署 plan 中让用户确认。

处理规则：

1. 只从当前 PMS 号对应的备注中提取 IP。
2. 优先使用包含“联调环境”的备注里的 IP。
3. 如果只有一个明确 IP，则作为默认部署机器 IP。
4. 如果没有找到 IP，或找到多个不同 IP，必须把候选情况说明给用户并等待确认。
5. 不要使用其他需求、历史部署任务或本地记忆里的机器 IP 作为默认值。

### 点播 dash 按需求号查完整分支名

点播 dash 的代码仓库：

```text
ssh://git@gitlab.qiyi.domain:10022/video-play/luna-rule.git
```

如果用户只给 PMS/需求号，例如 `5817`，可以远程查询匹配的分支名：

```bash
git ls-remote --heads ssh://git@gitlab.qiyi.domain:10022/video-play/luna-rule.git \
  | grep "$PMS"
```

查询后要把 `refs/heads/` 去掉，只保留部署接口需要的分支名。

必须排除自动 Nobug 分支：

```text
auto_*
auto_nobug_*
```

建议筛选方式：

```bash
git ls-remote --heads ssh://git@gitlab.qiyi.domain:10022/video-play/luna-rule.git \
  | awk '{print $2}' \
  | sed 's#refs/heads/##' \
  | grep "$PMS" \
  | grep -v '^auto'
```

如果只剩一个候选，就可以作为部署分支写入 plan；如果剩多个候选，列出来让用户确认。

## 参数注意事项

1. `envName` 是月神线上环境的分支名；保持空值表示默认 `master`。
2. `remoteAddr` 为空表示不固定设置 nginx 的用户 IP。
3. 单机部署时，部署机器 IP 只填一台机器；不要自动扩展为多台。
4. 部署描述不能为空，应保留用户原文，尤其是 PMS 编号。
5. 分支名必须使用用户给定值，不要自动改成 `origin/` 前缀。
6. 用户要求线上或国际站时，plan 中必须明确说出对应环境，避免误发测试环境。

## 查询月神环境分支

单机部署页面“新建部署”弹窗里的“月神配置数据”下拉框，不从 Git 分支查询，而是调用星图接口获取月神环境名列表。

接口：

```bash
curl -sS "http://starmap.qiyi.domain/dash/tools/deployCode/getEnvNames?token=$STARMAP_TOKEN"
```

返回结构：

- `data.online`：同步月神线上环境数据时可选的线上环境分支。
- `data.test`：同步月神测试环境数据时可选的测试环境分支。

按需求号前缀筛选示例：

```bash
curl -sS "http://starmap.qiyi.domain/dash/tools/deployCode/getEnvNames?token=$STARMAP_TOKEN" \
  | python3 -c 'import sys,json; d=json.load(sys.stdin)["data"]["online"]; print("\n".join(x for x in d if x.startswith("5817")))'
```

注意：

1. `envName` 是提交部署任务时传给 `/dash/tools/deployCode/commitTask` 的月神环境分支名。
2. 用户说“月神线上分支为某需求号开头那个”时，应先调用上述接口查 `data.online`，不要去 GitLab 查分支。
3. 如果匹配到多个环境分支，先让用户确认具体用哪个。

## 调用方式

1. 优先通过接口直接提交，不操作页面。
2. `/dash/tools/common` 下的部署接口依赖登录态；需要通过token方式请求。
3. 提交成功后必须查询部署任务列表确认，至少向用户反馈：
   - 新任务 ID。
   - 创建人。
   - 当前状态。
   - 关键参数是否与 plan 一致。

## 执行后校验

1. 查询代码部署任务列表，过滤最近创建的任务。
2. 对比任务参数中的分支、机器 IP、部署描述、profile 对应环境。
3. 提交任务后不要立即结束，应阻塞等待任务完成。
4. 阻塞轮询时每 10 秒查询一次任务列表，只关注本次新建的任务 ID。
5. 轮询过程中可以简短记录当前状态、当前步骤和状态描述，但最终回复只在任务成功或失败后给出。
6. 任务状态为成功时，向用户返回任务 ID、最终状态、部署机器、分支、描述、开始时间、更新时间，以及主要执行步骤。
7. 任务状态为失败时，向用户返回任务 ID、失败步骤、失败状态描述和相关 Jenkins uuid，不能只说失败。
8. 如果查询不到任务或响应为空，不要说成功，应继续排查登录态、权限或接口响应。
9. 如果轮询过程中出现 DNS、网络、接口解析失败等问题，应说明阻塞查询被中断的原因；不要把查询失败误判为部署失败或成功。
