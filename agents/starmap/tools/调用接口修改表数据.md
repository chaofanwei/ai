# SQL 接口使用说明

## 1. Token 鉴权

必须传入 token。token 关联到系统用户，接口会按该用户已有权限判断是否允许访问。

token 支持两种传入方式：

```text
请求参数：token
请求头：token 或 X-User-Token
```

Header 示例：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/query" \
  -H "Content-Type: application/json" \
  -H "X-User-Token: $USER_TOKEN" \
  -d '{"sql":"select 1 as ok"}'
```

参数示例：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/query?token=$USER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sql":"select 1 as ok"}'
```

未登录且未传 token 时，接口会返回 token 参数错误。


## 2. 查询数据库接口

接口地址：

```text
POST /apis/db/query
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sql` | String | 是 | 查询 SQL |

支持的 SQL 类型：

```sql
SELECT
SHOW
DESC
DESCRIBE
EXPLAIN
```

限制说明：

- 只允许单条 SQL。
- 不允许包含注释：`--`、`#`、`/* */`。
- `SELECT` 如果没有写 `limit`，系统会自动追加 `limit 1000`。

请求示例：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/query" \
  -H "Content-Type: application/json" \
  -H "X-User-Token: $USER_TOKEN" \
  -d '{"sql":"select 1 as ok"}'
```

返回示例：

```json
{
  "msg": "",
  "code": "A00000",
  "data": [
    {
      "ok": 1
    }
  ]
}
```

也可以查询业务表：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/query" \
  -H "Content-Type: application/json" \
  -H "X-User-Token: $USER_TOKEN" \
  -d '{"sql":"select id, name from st_project limit 10"}'
```

## 3. 修改数据库接口

接口地址：

```text
POST /apis/db/execute
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sql` | String | 是 | 修改 SQL |

支持的 SQL 类型：

```sql
INSERT
UPDATE
DELETE
```

限制说明：

- 只允许单条 SQL。
- 只支持单表操作。
- `UPDATE` 和 `DELETE` 必须包含 `WHERE` 条件。
- 不支持 `JOIN`、`ORDER BY`、`LIMIT` 等复杂修改 SQL。
- 不支持 DDL，例如 `ALTER TABLE`、`CREATE TABLE`、`DROP TABLE`。
- 执行 `UPDATE`、`DELETE` 前，会先把将被修改的数据备份到 `st_sql_operation_history.backup_data`。

INSERT 示例：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/execute" \
  -H "Content-Type: application/json" \
  -H "X-User-Token: $USER_TOKEN" \
  -d '{"sql":"insert into st_sql_operation_history (op_user, sql_text, op_type, table_name, success) values (\"curl_test\", \"select 1\", \"TEST\", \"st_sql_operation_history\", 1)"}'
```

返回示例：

```json
{
  "msg": "",
  "code": "A00000",
  "data": {
    "success": true,
    "historyId": 1,
    "affectedRows": 1
  }
}
```

UPDATE 示例：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/execute" \
  -H "Content-Type: application/json" \
  -H "X-User-Token: $USER_TOKEN" \
  -d '{"sql":"update st_sql_operation_history set error_msg = \"test_update\" where id = 1"}'
```

返回示例：

```json
{
  "msg": "",
  "code": "A00000",
  "data": {
    "success": true,
    "historyId": 3,
    "affectedRows": 1
  }
}
```

危险 SQL 示例，无 `WHERE` 会被拒绝：

```bash
curl -X POST "http://$HOST_DOMAIN/apis/db/execute" \
  -H "Content-Type: application/json" \
  -H "X-User-Token: $USER_TOKEN" \
  -d '{"sql":"update st_sql_operation_history set error_msg = \"bad\""}'
```

返回示例：

```json
{
  "msg": "仅支持单表UPDATE，且必须包含WHERE条件",
  "code": "P00001"
}
```

## 4. 注意事项

使用修改接口前，请务必确认 SQL 条件范围准确，尤其是 `UPDATE` 和 `DELETE` 的 `WHERE` 条件。

修改接口执行成功后，`st_sql_operation_history.op_user`、服务日志和告警消息里的操作人均为当前登录用户或 token 关联的系统用户。

当前没有启用 `transactionManager`，所以备份记录写入和修改 SQL 执行不是同一个数据库事务。正常情况下会先写备份再执行修改，但如果中途异常，需要根据接口返回和历史表记录人工确认执行状态。
